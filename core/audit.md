# Core Audit

This checklist operationalizes the judgment criterion of
[`core/philosophy.md`](philosophy.md) §10. It is used in two places with the
same mechanics:

- **Self-audit** — run against this repository (every rule, spec, template,
  and script) before every release tag. The result is recorded in
  `CHANGELOG.md`.
- **Target audit** — run against an installed project's `.context/` and
  Living layer, by the audit subagent or on user request.

## How to run

1. Enumerate the artifacts in scope (rules, specs, templates, scripts —
   or, for a target, cards, indexes, specs, dictionaries).
2. Apply every applicable checklist item below.
3. For each failure, record: artifact, item id, what failed, proposed fix.
4. Verdict is **pass** only with zero failures on D-items (derivation) and
   H-items (honesty); N/F-items may carry warnings with follow-ups.

## Checklist

### D — Derivation (every rule earns its existence)

- **D1.** Every rule/spec/mechanism serves first-degree mutual understanding
  or nth-degree understanding, and states which. If neither: flag for removal.
- **D2.** Derived documents cite `core/philosophy.md`; none restates it.
- **D3.** No rule contradicts another; conflicts are resolved by the core,
  and the resolution is written down where the conflict arose.

### F — First-degree devices (production-time mutual understanding)

- **F1.** Work begins with an explicit, recorded mode (interview result or
  one-line declaration) — never an implicit one.
- **F2.** Changes to agreed specs go through propose-then-confirm at the
  agreed autonomy level; no silent mode changes.
- **F3.** Specs lead with diagrams (node graph, flowchart) before prose.
- **F4.** Shared vocabulary is enforced: full naming, no unregistered
  abbreviations.

### N — Nth-degree devices (transfer-time understanding)

- **N1.** Every session leaves a result document (session card) with the
  required fields, indexed.
- **N2.** Machine metadata follows the machine-readable subset; indexes are
  regenerable; pointers resolve (no dead semantic links).
- **N3.** The consumption path works: on-demand retrieval (query procedure,
  report generation) can reconstruct past decisions from cards alone.
- **N4.** Derived artifacts are fresh (llm.txt not stale relative to
  `.context/`; regeneration preserves hand-maintained fields).

### H — Honesty of the record

- **H1.** Reconstructed raws are never labeled or described as captured ones
  (`raw_fidelity` is truthful).
- **H2.** Every binary asset has the required `alt` description; the record
  is understandable without the binary.
- **H3.** Every session card is self-sufficient: decisions, reasons,
  before/after, and affected files are understandable without raw access.
- **H4.** No secret or credential values are transcribed into cards or raws;
  upload paths scan before sending.

### P — Process (repository self-audit only)

- **P1.** Release checklist ran: self-audit recorded in CHANGELOG, examples
  regenerated by an actual install run, version bumped per SemVer.
- **P2.** `examples/` matches what a real install produces (committable
  artifacts), and is marked as instance demo, not spec.
