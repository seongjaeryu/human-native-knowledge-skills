# human-native-knowledge-skills (`hnk`)

> 사람이 실제로 이해할 수 있는 지식 시스템을 AI 에이전트가 구축하게 가르치는 스킬.

[English README](README.md)

## 문제의식: 지식 부채 (knowledge debt)

AI가 점점 더 많은 일을 대신하지만, 그 결과물은 사람이 제대로 검증하기 어려운 형태로 저장됩니다. AI와 함께 일한 당사자(사용자 1)조차 이미 부채가 생깁니다 — 제대로 확인하지 않은 결정들, 채팅 로그에만 남은 맥락. 사용자 2, 사용자 3으로 작업이 넘어갈수록 이해 비용은 복리로 불어납니다. 이것이 **지식 부채**입니다: **원금**은 생산 시점에 상호 이해되지 못한 채 쌓인 AI 산출물이고, **이자**는 시간이 지나고 사람(과 AI 세션)이 바뀔수록 복리로 커지는 이해 비용입니다.

AI 이전의 사람들에게는 검증된 해법이 있었습니다. 문서가 협업자 사이를 오가고, 그 위에서 논의가 이루어지고, 결과는 누구든 나중에 이어받을 수 있는 **결과 문서**로 정리되었습니다. 이 저장소는 그 방식을 agentic workflow에 적용합니다: **"사람 1명 + AI 1개"가 수행한 작업을, 이후의 어떤 사람이든 — 어떤 AI든 — 이해할 수 있게 기록합니다.**

한 줄 목표: **사람과 AI 모두가 이해하기 쉬운 지식의 축적.**

## 이 저장소의 정체

클론해서 쓰는 템플릿이 아닙니다. **AI 에이전트가 URL로 소비하는 스킬**입니다. AI 에이전트에게 이 저장소를 가리키면: 철학(`core/`)과 교과서(`skill/`)를 읽고, 템플릿을 대상 프로젝트의 `.context/` 구조로 인스턴스화하고, 무의존성 단일 스크립트(`scripts/hnk.mjs`)를 복사하고, 설치 인터뷰를 진행한 뒤, 이후 프로젝트의 지식 시스템 — 세션 아카이브, 시각 자산 인덱스, 작업 전 인터뷰 — 을 운영합니다.

`hnk`는 이 프로젝트의 등록된 공식 축약명입니다 — 이 스킬이 가르치는 네이밍 규칙("사전에 등록되지 않은 임의 축약 금지")의 시연 사례이기도 합니다.

## 저장소 지도

| 경로 | 역할 |
| --- | --- |
| `core/` | 헌법: 목표, 공리, 지식 부채 정의, 감사 기준 |
| `skill/` | AI 에이전트가 시스템을 배우는 교과서 |
| `templates/` | AI가 대상 프로젝트에 인스턴스화하는 파일들 |
| `scripts/hnk.mjs` | 단일 파일 무의존성 참조 스크립트 (Node 빌트인만) |
| `guides/` | 하네스 비종속 참고 가이드 (뷰어, 용어 강제, 스토리지) |
| `examples/` | 실제 설치 결과물 데모 프로젝트 |
